# 报价结构与视觉

## 对客表达

按门店问题 → 同行动作 → 市场机会 → 方案及原因 → 费用 → 交付组织。不强制六个独立章节，可以合并，但信息要清楚。每段回答一个客户关心的问题，少用术语；“客户现状”和“建议打法”不能混写。

内部核实口径、文件名、来源差异与通用免责声明不逐段搬入客户版。保留准确性：未核实说法删除或收窄，必要来源标注精简保留。每个主要结论集中讲一次，交付汇总只总结数量和周期。

数据优先整理为表格，不默认同时堆完整关键词截图。点评门店截图默认不放，诊断可以提取关键事实；笔记模板保留真实配图，让商家看懂实际内容形式。

## 客户版结构

采用暖白底、砖红头图、金额卡片、编号章节和有边框的图文卡。示例结构可以按需求删减，不把章节数当硬要求：

1. 品牌标题与本阶段一句话思路；摘要展示费用、内容数量、其他关键交付。包含项不得表现为额外数量。
2. 项目背景与品牌诊断；展示品牌关键词证据并解释含义。
3. 市场情况；关键词数据、地区边界和找店讨论证据。
4. 推广策略；两类或三类打法卡及用户决策流程。
5. 预算交付表；项目、数量配置、金额。单价是否展示依用户决定。
6. 内容方向；明确是提问、合集还是推荐笔记，避免未经确认分配数量。
7. 配图模板；左侧参考图、右侧解释。窄屏改上下排布。
8. 执行顺序与阶段目标；周期使用已确认表述。
9. 最终交付汇总；对齐报价表，说明素材安排、到店配合和记录。

## 排版与素材

- HTML 使用 UTF-8、中文 lang 和手机 viewport；不依赖外部字体加载。
- 默认约 1080 像素画布，正文约 18～22 像素；手机自适应。
- 图片保持比例，不拉伸，不为了装饰裁去 LIVE、关键词或必要正文。
- 可使用 data URL 将图片嵌入 HTML，使文件独立打开。
- 原始实况素材与案例截图有区别：案例只展示样式，不能作为本店发布素材。
- 参考截图不得标成品牌已完成案例。图中既有互动数据与本次评论交付分开。
- 缺图但可做方案时，说明该项目暂无配图，不用不相关截图填补。

## 费用与数量检查示例

以下数字仅用于验证算法，不是报价默认值：

- 需求帖 A：12篇，每篇45元，包含每篇3条评论。
- 需求帖 B：8篇，每篇70元，包含每篇3条评论。
- 分发：6条，每条110元；探店：4位，每位1条、180元。
- A 金额540元，B 金额560元，分发探店合并1380元，总计2480元。
- 小红书内容30条，包含评论60条。分发同步其他平台不增加小红书内容总数。

合并包金额可展示为1380元，数量显示6个代发＋4位探店；用户要求隐藏内部价时不展示110与180元。

## 导出检查

只在用户请求微信版后导出。截图前等待字体与所有图片加载，用章节或卡片边界计算切分点。完整长图和分图必须来自同一版本，不用旧版本覆盖当前数据。文件名清晰，最终只链接用户交付目录下的文件。
