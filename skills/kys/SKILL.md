# KY 公司内部业务工具箱

## 任务与路由

先恢复客户目录、已有材料与用户选择，只补问会改变交付的缺口。按任务加载一个对应子 Skill，不把所有规则一起载入。

| 用户任务 | 执行入口 |
| --- | --- |
| 查询历史报价、单价、套餐或向报价库入库 | [kys-pricing](references/modules/kys-pricing/SKILL.md) |
| 餐饮小红书基础截图、补图清单、关键词、诊断、方案、报价或修改 | [kys-diagnosis](references/modules/kys-diagnosis/SKILL.md) |
| 已确认的其他商家方案，或仅做通用报价排版 | [kys-quote](references/modules/kys-quote/SKILL.md) |
| 生成、填写或修改固定推广合同、年度框架合同 | 独立 `$kys-contract`，按当前技能目录读取其 SKILL.md |
| 其他销售卡点、需求、预算或成交路径 | 先整理事实、缺口与当前目标，调用环境中匹配的诊断或目标澄清 Skill |

餐饮小红书报价归餐饮子 Skill；用户明确指定通用版式模块时沿用选择。单纯改价格、排版或导图不重启市场诊断。

## 共同约定

两个报价子 Skill 均读取 [报价共同交付规则](references/quote-common.md)，共用确认数据与导图工具。默认 HTML，图片按请求生成；用户的明确格式要求优先。

- 客户事实来自本轮材料，案例只作视觉参考；不虚构预算、承诺或效果。
- 数量、金额、周期、平台口径一致；内部信息不进入客户版。
- 已确认数据可交接合同，但报价完成不自动触发合同制作。
- 合同是独立 Skill，自己维护母版、脚本与验收；本入口不混入合同条款。
- 成品必须实际生成、检查并交付。未解决金额或交付歧义时只交可审阅初稿。

## 维护

报价子 Skill 保存在 `references/modules/`，共享规则只维护一份。合同通过技能名称路由，不复制母版或条款进报价模块。新增能力明确输入、产出和边界后再加入路由。
