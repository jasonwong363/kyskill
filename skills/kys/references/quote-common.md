# 报价共同交付规则

餐饮方案与通用报价共用本规则。用户明确要求优先。

## 输出模式

- 默认生成 HTML；只要 HTML 或先审阅时，不导出 PNG。
- 用户请求微信图片、截图或 PNG 时，从当前 HTML 导出完整长图、编号分图及 ZIP；只要求图片时可仅交付图片，保留 HTML 源文件。
- 修改金额、配置或策略后旧图片失效；没有导图请求不重做，有请求则重新导出全部分图，只链接当次 manifest 的文件。

## 数据与事实

在客户目录 `05_方案与报价/项目确认数据.json` 保存内部共享数据。读取对话与已有文件后更新，不要求用户填写 JSON。至少包含 brand、city、store_scope、items、total_amount、service_period、material_owner、confirmed、pending、source_notes、revision。每个 items 项记录项目名、配置、数量与单位、单价或套餐金额、包含项、平台、金额和确认状态；未知字段用 null，不能用 0 代替未知。

逐项核对数量乘单价、套餐价、总计、包含评论、到店人数与跨平台条数。套餐不强拆单价；包含项不重复计费。正文、预算表、交付汇总均来自这份确认数据。内部成本和隐藏单价不进入客户版。它是内部记录，不随客户文件打包。

仅使用已确认配置生成正式报价；未确认部分留在内部 pending，审阅初稿明确标出缺口。不得复用其他客户事实、价格、效果或预算。实际发布、邀约、付款不属于报价任务。

## 独立文件与导出

HTML 图片嵌入 data URI，不依赖外部图片、字体或本机文件。选用完整参考 HTML 时仅复用视觉，替换全部客户事实和图片。制作后检查桌面与手机，无横向溢出。

共用工具为工具箱根目录 `scripts/export-wechat.cjs`，两个子 Skill 的原脚本入口转调该工具。工具等待字体与图片加载，保护表格、图片、卡片完整性；过长块报告后调整版式再导出，不硬切。逐张查看清晰度、切点和尾页，脚本成功不代替视觉检查。

## 合同交接

只有用户要求合同时才调用独立 `$kys-contract`，不因报价完成自动生成合同。传递共享数据路径与当前确认版本；合同 Skill 自己读取 intake 并映射为其 JSON，母版、法律条款和合同脚本留在合同 Skill。

只传递已确认品牌、签约主体、交付、总金额、周期与平台；没有签约主体或日期则补齐。没有确认周期时明确提示合同默认从签订日期起 45 天，记录该默认来源；若现有报价周期不同，优先使用已确认周期，存在矛盾时解决后再交付。合同需要合并超过五行交付时，保留原始项目映射与合计，不丢失交付。
