# 报价共同交付规则

餐饮方案与通用报价共用本规则。用户明确要求优先。

## 主版本与跨设备交接

- MacBook 是报价及 kys 维护主机；Mac mini 默认查看成品。无法确认设备时，不把当前环境当成 MacBook；用户已指定主目录时沿用，不创建第二套主目录。
- 每个客户只维护一份 `05_方案与报价/项目确认数据.json`。先恢复它与最新用户修订，再生成报价；保留已有目录结构，不为统一命名搬动历史文件。
- 正式对客文件采用“品牌_报价_YYYYMMDD_vNN”命名。同日修改递增版本，保存已发客户版本；日期按用户时区。HTML、导图和文字版引用同一确认版本，旧图片不得作为新版交付。
- 用户已确认的共享资料目录可用于跨设备查看。iCloud 是否开启、实际目录、同步完成状态都需要验证；未核实不能宣称已配置。存在冲突副本时先对比内容及用户最新确认，不单凭文件修改时间覆盖。
- 客户源资料、报价数据与成品归客户目录；kys 规则和脚本归技能维护目录。日常报价不在技能目录或项目 `sources/` 中写客户事实。
- 这份规则只规定工作方式，不授权批量迁移、删除其他设备文件、修改系统同步设置或推送远端仓库。安装或更新技能后核对实际安装目录内容，未替换时明确报告仍为更新副本。

## 输出模式

- 默认生成 HTML；只要 HTML 或先审阅时，不导出 PNG。
- 用户请求微信图片、截图或 PNG 时，从当前 HTML 导出完整长图、编号分图及 ZIP，并在图片之后附上可直接复制给客户的文字版报价；保留 HTML 源文件。仅当用户明确说“只要图片，不要文字”时省略文字版。
- 修改金额、配置或策略后旧图片失效；没有导图请求不重做，有请求则重新导出全部分图，只链接当次 manifest 的文件。

## 图片后的文字版报价

文字版使用同一份项目确认数据与最新修订，包含客户名称、各推广项目、账号或内容类型、单价、数量、小计、同步平台、包含服务与总金额。已确认的控评按每帖或总量的实际口径写清楚；跨平台同步按确认的计价方式表达，不自行放大内容条数。未确认字段不编造，不把内部待办写入对客文案。

用独立、可复制的客户消息呈现文字版；支持 writing block 的环境使用 chat_message。文字版紧接图片交付，不让用户再次索要。改价、改平台或改配置并重新出图时，一并更新文字版；用户本轮明确指定其他格式时优先遵从。

## 数据与事实

在客户目录 `05_方案与报价/项目确认数据.json` 保存内部共享数据。读取对话与已有文件后更新，不要求用户填写 JSON。至少包含 brand、city、store_scope、items、total_amount、service_period、material_owner、confirmed、pending、source_notes、revision。每个 items 项记录项目名、配置、数量与单位、单价或套餐金额、包含项、平台、金额和确认状态；未知字段用 null，不能用 0 代替未知。

逐项核对数量乘单价、套餐价、总计、包含评论、到店人数与跨平台条数。套餐不强拆单价；包含项不重复计费。正文、预算表、交付汇总均来自这份确认数据。内部成本和隐藏单价不进入客户版。它是内部记录，不随客户文件打包。

仅使用已确认配置生成正式报价；未确认部分留在内部 pending，审阅初稿明确标出缺口。不得复用其他客户事实、价格、效果或预算。实际发布、邀约、付款不属于报价任务。

## 周期、费用与执行边界

涉及按月、多店、达人浮动费用、预算转项或陪跑附加执行时，读取 [客户项目协作](client-workflow.md) 的“配置修改与预算”和“服务范围与投入判断”。确认数据补充总预算与单月预算、月数、按店／共享范围、费用性质、执行方及比例计费基数；未知用 null。不得为凑齐预算擅自加项。合同总额、已收款和广告消耗分开。

## 本地案例素材库

案例库位置优先从用户指定目录或当前环境配置恢复；无法定位时仅询问路径，不递归扫描无关个人目录。已定位案例库的索引为 `案例索引.json`（另附 CSV），截图副本放在 `原始截图/`。用户提供的新截图先查看实际内容，再按平台、行业、内容类型和适用项目记录索引，保留原文件路径、截图日期、作者、标题、来源链接（未知用 null）与 SHA-256；依据哈希避免重复入库，不移动或覆盖用户原图。

报价需要参考图时先查索引，再查看候选原图，按当前项目选择。未经确认的合作归属统一标为内容形式参考；截图中的互动不能当作己方效果或控评成果，粉丝量未核实不能证明千粉配置。选用与暂不采用的理由保留在内部索引，对客只展示必要的来源与形式说明。

## 独立文件与导出

HTML 图片嵌入 data URI，不依赖外部图片、字体或本机文件。选用完整参考 HTML 时仅复用视觉，替换全部客户事实和图片。制作后检查桌面与手机，无横向溢出。

共用工具为工具箱根目录 `scripts/export-wechat.cjs`，两个子 Skill 的原脚本入口转调该工具。工具等待字体与图片加载，保护表格、图片、卡片完整性；过长块报告后调整版式再导出，不硬切。逐张查看清晰度、切点和尾页，脚本成功不代替视觉检查。

## 合同交接

只有用户要求合同时才调用独立 `$kys-contract`，不因报价完成自动生成合同。传递共享数据路径与当前确认版本；合同 Skill 自己读取 intake 并映射为其 JSON，母版、法律条款和合同脚本留在合同 Skill。

只传递已确认品牌、签约主体、交付、总金额、周期与平台；没有签约主体或日期则补齐。没有确认周期时明确提示合同默认从签订日期起 45 天，记录该默认来源；若现有报价周期不同，优先使用已确认周期，存在矛盾时解决后再交付。合同需要合并超过五行交付时，保留原始项目映射与合计，不丢失交付。
